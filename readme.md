# Project No Doubt（确任）产品文档 PRD v1.0

## 1. 项目基本信息

**项目英文名**：Project No Doubt
**项目中文名**：确任
**命名解释**：
“确任”中的“任”取“任务”的“任”，也有“确认托付、确实可任、值得信任”的含义。
“No Doubt” 对应产品底层价值：**让用户对任务、对人、对流程、对结果更少怀疑。**

**产品定位**：
一个围绕“任务悬赏、技能交换、同城搭子、故事沉淀”构建的轻社交交易平台。

**产品愿景**：
让有需求的人快速找到靠谱的人，让有能力的人更容易被看见，并让每一次连接都可能发展成有趣的故事和真实关系。

**产品使命**：
用更低门槛、更可信、更有趣的方式，重构人与人之间的任务协作和技能互助。

---

## 2. 背景与机会

现在的同类产品大多有明显割裂：

一种偏工具交易，只解决“发单—接单—结束”，效率有了，但没有关系和留存。
一种偏技能交换和兴趣社交，有氛围，但弱交易、弱变现。
还有一种偏社交内容平台，大家逛得开心，但落不到真实协作和付费。

确任想解决的是这个断层：

**既能发任务赚钱/办事，又能交换技能建立连接，还能沉淀成内容和社区。**

### 2.1 市场启发

Swap 已经验证了“技能共享 + 技能交换 + 搭子 + 轻变现”这一套入口组合，而且明确把“技能社交”作为核心表达。([swapapp.cn][1])
闲创无忧已经验证了“快速发布、在线直聊、供需资源对接、置顶曝光”这套轻交易逻辑。([xianchuangwuyou.com][2])
JuJu 的方向说明，用户对“基于信任的真实社交连接”是有需求的。([App Store][3])

### 2.2 我们的机会

确任不直接复制任何一个参考物，而是做中间层融合：

* 用任务模型带来明确需求与订单
* 用交换模型降低首单门槛与冷启动成本
* 用搭子模型建立轻社交和粘性
* 用故事流承接传播和内容增长
* 用门店承接高频城市需求，形成线上到线下闭环

## 3. 产品定位与边界

## 3.1 一句话定位

**一个让任务更可信、技能更好卖、连接更有趣的城市协作平台。**

## 3.2 核心价值主张

对需求方：

* 找人更快
* 流程更安心
* 价格更透明
* 更容易找到“对味”的人

对供给方：

* 技能可展示
* 信用可积累
* 接单门槛低
* 容易获得同城机会

对平台：

* 可交易
* 可内容化
* 可社交化
* 可线下落地

## 3.3 产品边界

第一阶段不做：

* 全职招聘
* 重度企业外包
* 高风险专业服务
* 陌生人约会 App
* 医疗、法律、金融承诺类服务
* 成人、灰产、危险类委托

## 4. 目标用户

## 4.1 核心用户群

### A 类：轻需求发布者

特征：

* 20–40 岁城市用户
* 有零散需求
* 不想走传统外包或熟人求助
* 需要快速、低成本、轻量协作

典型需求：

* 帮拍照
* 陪看展
* 帮跑腿
* 简历优化
* 陪练语言
* 临时搭子
* 活动协助

### B 类：轻技能供给者

特征：

* 有某种技能/时间可出售
* 希望赚零花钱或扩大关系
* 不想进入重平台或复杂接单系统

典型技能：

* 摄影
* 修图
* 英语
* PPT
* 短视频
* 宠物照看
* 运动陪练
* 活动主持
* 城市向导

### C 类：兴趣社交用户

特征：

* 不一定为赚钱
* 但愿意通过搭子、交换、同城活动建立关系
* 容易被有趣任务和故事吸引

## 5. 用户痛点

### 发布者痛点

* 不知道去哪里找合适的人
* 熟人不好意思开口
* 平台太重，流程太复杂
* 担心鸽子、担心被骗、担心效果差
* 发了需求没人理

### 接单者痛点

* 会点技能但无处展示
* 不知道哪里有轻量机会
* 传统平台抽佣高、门槛高
* 首单难、信任难建立
* 容易遇到无效沟通

### 平台级痛点

* 冷启动双边问题
* 用户信任建立慢
* 纯交易产品留存差
* 纯社交产品变现弱

## 6. 产品目标

## 6.1 第一阶段目标（MVP，0–3 个月）

目标是跑通最小闭环：

* 用户可注册
* 用户可发布任务/交换
* 用户可报名/申请
* 双方可聊天
* 可形成订单
* 可完成评价
* 可进行基础审核与举报

核心指标：

* 完成首批 1000 个有效发布
* 首月撮合成功率 > 15%
* 首月完成订单数 > 200
* 发布到首个申请的中位时长 < 24h
* 首单完成率 > 60%

## 6.2 第二阶段目标（3–6 个月）

* 上线搭子和逛逛内容流
* 增加信用分与认证系统
* 上线置顶/加急/推荐位
* 建立同城种子社区

## 6.3 第三阶段目标（6–12 个月）

* 开启城市主理人机制
* 试点线下门店/活动空间
* 形成线上发布、线下承接的城市节点

## 7. 核心产品理念

确任的核心不是“接单工具”，而是一个三层结构：

### 第一层：任务

解决“我有事，要找人”。

### 第二层：交换

解决“我也许不想直接花钱，但愿意用技能/时间来换”。

### 第三层：故事

解决“这件事值得被看见，值得留在平台上继续传播”。

这三层叠起来，平台才不会只剩一次性交易。

## 15. 商业化设计

## 15.1 第一阶段收费策略

建议第一版不要一上来就“发布收费”。

### 任务

* 发布免费
* 成交抽佣 8%–15%
* 加急、置顶、推荐位收费

### 交换

* 暂不抽佣
* 可做会员权益或交换券体系

### 搭子

* 普通免费
* 商业活动型收服务费

### 这样设计的原因

Swap 明确用首单低价来降低首单门槛，说明早期最重要的是先跑通交易，而不是先提高收费门槛。([swapapp.cn][1])
闲创无忧也把“置顶曝光、会员曝光”作为增强项，而不是唯一入口。([App Store][5])

## 15.2 后续收费项

* 置顶
* 加急
* 城市推荐位
* 官方认证
* 企业任务套餐
* 主理人活动抽成
* 门店服务抽成

## 16. 运营策略

## 16.1 冷启动城市

建议先做 1 个城市，如上海。

原因：

* 同城任务天然更容易发生
* 用户感知更强
* 线下延展更顺

## 16.2 冷启动供给

优先吸引：

* 摄影师
* 探店博主
* 语言陪练
* 简历/PPT/设计轻服务
* 宠物相关服务
* 同城运动搭子
* 活动协助人员

## 16.3 冷启动内容

首批官方任务建议偏“有故事性”：

* 帮我拍一组生日照
* 陪我完成一个周末愿望
* 帮我策划一个小告白
* 帮我带猫去洗护
* 帮我做一版求职简历
* 陪我去探索一家奇怪的小店

## 21. 风险与应对

### 风险 1：双边冷启动

应对：

* 先做一个城市
* 官方发首批任务
* 优先引入轻技能用户
* 用交换降低首单门槛

### 风险 2：信任与欺诈

应对：

* 手机 + 实名
* 托管支付
* 信用分
* 举报与仲裁
* 黑名单

### 风险 3：内容变形

应对：

* 严格类目审核
* 敏感词过滤
* 高风险任务人工复核

### 风险 4：平台不够有趣

应对：

* 强化故事流
* 强化同城任务感
* 打造精选案例和主题活动

## 22. 成功判断标准

如果确任做对了，用户不会把它理解为“兼职平台”或“约人 App”。

用户会说：

* “我在这上面找人帮我做事很方便。”
* “我有点技能也能在这里被看见。”
* “这里总能遇到一些有趣的人和事。”
* “我会想打开看看今天同城发生了什么。”

这就是产品真正成立的信号。

## 23. 项目总结

**Project No Doubt / 确任** 的核心不是单点功能，而是一个完整闭环：

**任务** 带来需求和交易
**交换** 降低门槛和冷启动成本
**搭子** 增加社交和留存
**故事流** 提供传播和增长
**门店** 承接高频城市连接

一句话概括：

**确任，是一个让任务更可信、技能更有价值、人与人连接更自然的城市协作网络。**
