# 确任 MVP 页面原型清单与状态说明

## 1. 文档目的

这份文档用于承接 [01-mvp-launch-plan.md](/Users/dreamyyxt/Projects/Nodoubt/docs/01-mvp-launch-plan.md)，为产品、UI 和研发提供统一的页面设计输入。

它回答 4 个问题：

- 首版到底要画哪些页面

- 每个页面的主操作是什么

说明：
这里以 Flutter 客户端的用户端页面为主，后台页面只做轻量清单，不展开交互细节。

## 2. 首版主流程

MVP 先覆盖 4 条主流程：

1. 新用户注册并完善资料
2. 浏览任务/交换并申请
3. 发布任务/交换并等待申请
4. 沟通后创建订单并完成评价

如果这 4 条流程在原型层是顺的，首版就可以进入 UI 设计和开发。

## 4. 全局设计原则

### 4.1 首版设计目标

首版不是做一个“内容很多”的 App，而是做一个“路径很清晰”的 App。

所以页面设计优先级是：

- 让用户知道下一步该做什么
- 让交易状态足够清楚
- 让信任信息足够靠前
- 让核心操作少而明确

### 4.2 全局固定元素

所有核心页面建议统一这些组件思路：

- 顶部导航栏
- 城市信息展示
- 用户信用/认证信息
- 统一状态标签
- 底部主操作区
- 举报入口

### 4.3 全局状态规范

大多数页面都应考虑以下状态：

- 初始加载
- 空状态
- 正常内容态
- 异常态
- 无权限态

## 5. 页面详细清单

## 5.1 启动页

### 页面目标

完成品牌露出、登录态判断和基础初始化。

### 核心元素

- Logo
- 品牌名“确任 / No Doubt”
- 启动背景图形或品牌色
- 加载状态

### 页面状态

- 冷启动加载中
- 已登录，跳首页
- 未登录，跳登录页
- 初始化失败

### 主操作

无显式操作，以跳转为主。

## 5.2 登录/验证码页

### 页面目标

完成手机号验证码登录。

### 核心元素

- 手机号输入框
- 验证码输入框
- 获取验证码按钮
- 登录按钮
- 用户协议与隐私政策勾选

### 页面状态

- 默认态
- 手机号格式错误
- 验证码发送倒计时
- 登录中
- 登录失败

### 主操作

- 获取验证码
- 登录

## 5.3 完善资料页

### 页面目标

让新用户在最短路径内补齐基本资料，进入可发布、可申请状态。

### 核心元素

- 头像上传
- 昵称输入
- 城市选择
- 个人简介
- 技能标签选择
- 兴趣标签选择

### 页面状态

- 首次进入引导态
- 必填项未完成
- 可提交态
- 提交成功

### 主操作

- 保存并进入首页

### 设计提醒

首版不要要求用户一次性填写太多字段，重点是完成基本可用资料。

## 5.4 我的主页

### 页面目标

承载个人信息、信用信息和个人业务入口。

### 核心元素

- 头像、昵称、简介

- 信用分
- 完成单数
- 评分概览
- 我的发布

- 我的订单
- 设置入口

### 页面状态

- 自己查看自己的主页
- 资料较完整
- 资料不完整提醒
- 信用正常
- 信用受限提示

### 主操作

- 编辑资料
- 查看我的发布
- 查看我的申请
- 查看我的订单

## 5.6 首页列表页

### 页面目标

承载任务和交换的主要发现路径。

### 页面结构

- 顶部城市选择
- 搜索框
- 一级频道切换：任务 / 交换
- 分类或标签筛选区
- 信息流列表
- 悬浮发布按钮或明显发布入口

### 卡片核心信息

- 标题
- 简述
- 标签
- 预算或交换说明
- 线上/线下
- 城市
- 发布时间
- 发布者头像、昵称、信用信息

### 页面状态

- 默认推荐流
- 切换到任务频道
- 切换到交换频道
- 无数据空状态
- 加载更多
- 网络异常

### 主操作

- 搜索
- 筛选
- 进入详情
- 去发布

### 设计提醒

首版不要把首页做得像内容社区，更像“可信的同城机会列表”。

## 页面跳转主链路

### 链路 1：浏览申请

首页 -> 详情页 -> 申请页 -> 提交成功 -> 会话页或我的申请

### 链路 2：发布接单

发布页 -> 发布任务/交换页 -> 待审核 -> 发布详情管理页 -> 收到的申请 -> 会话页

### 链路 3：订单完成

会话页 -> 创建订单 -> 订单详情页 -> 提交完成 -> 确认完成 -> 评价页

## 7. 后台页面轻量清单

首版后台先追求够用：

- 管理员登录页
- 用户审核页
- 发布内容审核页
- 举报处理页
- 订单争议页
- Banner/推荐位配置页

后台首版主要功能：

- 搜索
- 筛选
- 查看详情
- 审核通过/驳回
- 封禁/解封
- 记录操作日志

## 8. 原型输出优先顺序

如果现在开始画原型，建议按这个顺序推进：

1. 首页列表页
2. 任务详情页
3. 发布任务页
4. 申请页
5. 会话页
6. 订单详情页
7. 我的主页
8. 发布交换页
9. 交换详情页
10. 我的申请/我的发布/订单列表页

原因：

这 10 个页面已经足够串起 MVP 核心闭环，其他页面可以在这个基础上快速补完。
